# 006 – Photo Slots and placing Photos

Status: done · Depends on: 003, 005

## What

Add rectangular Photo Slots to a Page and fill them by dragging Photos from the grid. This creates Placements.

## Acceptance criteria

- [x] Photo Slots can be added, moved, resized and deleted on a Page.
- [x] Slot geometry is stored as fractions of the Page.
- [x] Dragging a Photo from the grid onto a Photo Slot creates a Placement. Dropping onto an occupied Slot replaces its Photo.
- [x] A new Placement fills the Slot with a centred Crop.
- [x] The editor draws Placements from cached **previews** (about 2048 px on the long edge, generated by Rust), never from originals.
- [x] A Placement stores the Photo's path relative to the Library root.

## Implementation and verification

- **Domain** (`src/core/slots.ts`): Photo Slots and Placements.
  - Slot geometry is stored as fractions of the trim Page. A Slot may extend
    into the Bleed; moving and resizing clamp it to the bleed box. The minimum
    size is 2% of the Page.
  - Placements store the Photo's Library-relative path and a Crop, as fractions
    of the upright Photo.
  - A new or replaced Placement gets a centred Crop that fills the Slot. On
    resize, the Crop is refit around the same centre so it keeps filling the Slot.
  - Album files are validated on load. The schema version is still 1, because no
    earlier files contain Slots.
- **Rust** (`photo_preview`): returns cached upright JPEG previews, at most
  2048 px on the long edge.
  - Previews are stored per machine in app data, keyed by the Photo's file
    revision.
  - Thumbnails and previews share one cached-rendition helper. It downscales
    before applying the EXIF orientation.
- **Editor rendering:** Konva draws Slots and Placements, from previews only
  (ADR 0002).
- **Editor interaction:** transparent HTML overlays handle selecting, moving,
  resizing from the bottom-right handle, deleting (the toolbar button or the
  Delete key) and dropping Photos.
  - Photo tiles in the grid are HTML drag sources with a phalbummakr-specific
    payload.
  - Invalid payloads are ignored.
- **Tests:**
  - Domain tests cover add, move, resize, delete, place, replace and validation.
  - A Rust test covers previews.
  - PhotoBrowser tests check the drag payload.
  - Workspace tests cover the Slot lifecycle and dropping or replacing a
    Placement, both persisted.
- **Manual check:** the integrated browser, with a mocked desktop bridge.
  Dropping a Photo, moving and resizing a Slot (which clamped at the Bleed) and
  saving all worked. Konva rendered the cropped preview inside the Slot.

## Review

The code review (standards and spec) found:
- a thumbnail regression: rotated Photos were oriented at full size before
  downscaling;
- a possible exception when a forged drag payload is dropped.

Both are fixed. The hidden-folder rule shared by scanning and rendition lookup
was extracted into one helper. Adding a Slot no longer sets selection inside a
state updater.

## Future considerations (low priority)

- Album validation does not check that Slots stay inside the bleed box. This is
  deliberate: shrinking the Bleed in Album settings must not make an Album
  unloadable. Consider clamping or flagging Slots when the Bleed changes.
- Resizing works only from the bottom-right handle. Consider adding edge and
  corner handles, and keyboard nudging.
- `x, y, width, height` travel together in Slots, Crops and render props.
  Consider a shared rectangle type if this keeps spreading.
- `exactRecord` in `slots.ts` duplicates the `record` helper in `album.ts`.
  Consider sharing it.
- The "orientations 5–8 swap width and height" rule exists in both TypeScript
  (`placePhoto`) and Rust (`orient`).
- Native WebView2 smoke test of mouse drags and HTML drag-and-drop from the
  grid (see 005).
